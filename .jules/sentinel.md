## 2024-05-18 - Hardcoded JWT Secret Vulnerability and Environment Variables Injection
**Vulnerability:** A hardcoded, insecure default secret (`dev-secret-change-me`) was utilized in `AuthModule` and `JwtStrategy` inside the NestJS backend to verify and sign tokens, resulting in a critical cryptographic weakness if an environment string was inadvertently omitted in production. Furthermore, secrets were accessed directly via `process.env`.
**Learning:** Hardcoded fallback values for sensitive operations—even meant purely for "dev" convenience—often accidentally make it into deployed instances. This weakens cryptographic mechanisms heavily and introduces predictability. Directly referencing `process.env` scattered across components makes configuration fragile and difficult to test securely or validate properly.
**Prevention:** Rely entirely on configuration injection (like NestJS `@nestjs/config` `ConfigService`) to retrieve secrets and enforce strict checks—failing immediately on startup if crucial sensitive settings (like `JWT_SECRET`) are missing. Avoid providing insecure fallback defaults in source code for cryptographic keys.
